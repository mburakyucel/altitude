# Landscape — existing tools against the requirement

*Researched 2026-08-29 against official docs/repos (a research agent, 90 fetches; URLs inline so claims can be checked). Requirement and vocabulary: `VISION.md` (L1 worker / L2 orchestrator / L3 coordinator; Decision vs FYI; subscription CLIs; self-hosted + phone; context hygiene; automatic validation; rule provenance).*

## Verdict in one paragraph

**No maintained tool combines** a long-lived per-project executive agent, an enforced proposal → go/no-go → execute gate, separate orchestrator sessions driving both Claude Code and Codex on subscription seats, phone/voice access, and explicit context hygiene. Two tools come close from opposite directions — **Paperclip** has the governance (a "Decisions" attention feed, plan approvals, `claude_local`/`codex_local` adapters that run exactly the `claude --print --output-format stream-json --resume` loop we planned) but weak context hygiene and a heavy "AI company" metaphor; **OpenClaw** has the platform (mobile apps with approvals, voice, real memory hygiene, sub-agent hierarchy, deterministic approval pipelines) but is a very large, fast-churning, security-incident-prone codebase whose Claude path depends on a policy gray area. **Claude Code's own recent features** are the best set of building blocks and map almost one-to-one onto `ARCHITECTURE.md`. Nobody has built the parts that matter most to Burak: Decision/FYI discipline at L3, rule provenance with audit, supervisor-driven context rotation, and cross-engine validation by default. Those are small.

## The two candidates, honestly

**Paperclip** (https://github.com/paperclipai/paperclip · https://paperclip.ing/product/governance/). What fits: Decisions v1 (https://paperclip.ing/changelog/v2026.817.0/) is our Decision channel and inbox already built — agents propose typed multi-option actions, humans decide from a prioritized attention feed, effects are executed and audited; plan approval binds to plan revisions; one-click pause of an agent or the whole company; monthly budgets per agent; heartbeats (cron/events/@mentions) wake agents. The `claude_local` adapter (https://github.com/paperclipai/paperclip/blob/master/docs/adapters/claude-local.md) runs `claude --print - --output-format stream-json --resume <id>` with session ids persisted across heartbeats — the exact mechanism in `ARCHITECTURE.md` §3; `codex_local` chains threads the same way. Community `paperclip-plugin-telegram` (https://github.com/mvanhorn/paperclip-plugin-telegram) adds push, inline approve/reject, and voice-message intake. What doesn't: context hygiene is manual (docs offer session reset; issues #635 stale resumed sessions, #3596 forced rotation on CLAUDE.md change — https://github.com/paperclipai/paperclip/issues/3596); no FYI channel distinct from the feed; no rule provenance; no validation loop; the org-chart/company metaphor adds concepts we do not want (CEO agent, hiring). Also `dangerouslySkipPermissions` defaults to true in the Claude adapter.

**OpenClaw** (https://github.com/openclaw/openclaw · https://docs.openclaw.ai). What fits: sub-agents with `maxSpawnDepth` 1–5 and an explicit orchestrator role (https://docs.openclaw.ai/tools/subagents); Claude Code / Codex / others as children over ACP, with harness questions surfacing as chat prompts (https://docs.openclaw.ai/tools/acp-agents); native Codex app-server integration; **Lobster** — a deterministic workflow engine where `approval: required` pauses a pipeline with a durable resume token and the prompt lands in chat (https://docs.openclaw.ai/tools/lobster) — the deterministic gate we specified; the best memory hygiene in the field (memory flush before compaction, nightly "dreaming" with human-reviewable summaries, https://docs.openclaw.ai/concepts/memory); official phone apps with approvals and Talk Mode. What doesn't: 388k-star codebase shipping ~1.5k PRs per beta, documented security incidents, config sprawl; and the Claude path — Anthropic blocked third-party OAuth harnesses on 2026-04-04 (https://docs.openclaw.ai/providers/anthropic), so OpenClaw's supported routes are an API key or its `claude-cli` backend that drives the locally logged-in binary "drawing from the signed-in subscription's limits", which is a policy gray area (see below). Recommendation: **borrow** (memory flush before compaction, Lobster's approval semantics, the depth-limited orchestrator role), do not adopt.

## Native Claude Code features that change `ARCHITECTURE.md` (newer than `BUILDING-BLOCKS.md`)

- **Remote Control is GA**, and `claude remote-control --spawn worktree --capacity 32` lets the phone *start* sessions on this PC; permission prompts and **`AskUserQuestion` stay open on the phone until answered**, with push (https://code.claude.com/docs/en/remote-control). That is a real, tappable approval gate for Decisions — structured options, not chat inference — available in phase 1 with zero UI work. `AskUserQuestion` is not available inside subagents, so L3 (the top-level session) asks it. RC requires a claude.ai login (no API key / proxy) — fine for us.
- **`claude agents`** is now a console with *Needs input / Working / Ready for review* buckets and voice dispatch (https://code.claude.com/docs/en/agent-view); `claude --bg --name <x>`; **background sessions idle-stop after ~1h unless pinned** → L2s must checkpoint-and-exit when they need a Decision, and be resumed with the answer, never sit waiting.
- **Cross-session messaging is GA** (`ListAgents`/`SendMessage`, `notify_when_idle`, inbound `hold|accept|refuse`, cross-machine via RC — https://code.claude.com/docs/en/cross-session-messaging): L2 → L3 report-back and L3 → L2 answers need no custom bus.
- **Hooks** have `http` handlers (33 events incl. `PermissionRequest`, `PreCompact`/`PostCompact`, `SubagentStop`, `Stop`) — the Stop-hook webhook needs no `curl`; `PreCompact` can archive the transcript first (https://code.claude.com/docs/en/hooks).
- Headless adds `--max-budget-usd`, `--restricted`; `.claude/rules/` exists for modular rules; `/goal` loops; `/rewind`; `claude -p "…" --cloud <id>` steers cloud sessions programmatically.
- **Claude Dispatch** (phone → Desktop, pushes when it "needs your go-ahead") is a built-in executive gate but needs the Desktop app open — a fallback, not the plan (https://support.claude.com/en/articles/13947068).
- **Codex**: app-server JSON-RPC (`thread/start|resume|fork|archive|compact`, `turn/steer`, server-initiated `requestApproval` / `requestUserInput` — https://learn.chatgpt.com/docs/app-server), hooks GA with a Claude-compatible schema, official **codex-plugin-cc** (Claude-parent → Codex-worker, https://github.com/openai/codex-plugin-cc). Codex Remote only pairs with an awake desktop app, so Codex never fronts the phone.

## What to borrow into the custom build

Symphony's SPEC (tracker state as the gate; per-issue workspace; stateless recovery — https://github.com/openai/symphony/blob/main/SPEC.md) · Paperclip's Decisions feed shape (typed options, prioritized attention) · OpenClaw's memory flush-before-compaction and Lobster's durable approval tokens · Beads (https://github.com/gastownhall/beads) or Backlog.md as a ready-made durable ledger if `~/.altitude/<project>/tasks/` outgrows flat files · Happy / Paseo (https://github.com/slopus/happy · https://github.com/getpaseo/paseo) as self-hosted phone/voice clients if Remote Control falls short · ralph-orchestrator / `/goal` for "keep working until done".

## Policy risk to settle (Decision for Burak)

Anthropic's 2026-04-04 change bans third-party harnesses from using claude.ai OAuth, and the Agent SDK terms say no claude.ai login for third-party products (https://alternativeto.net/news/2026/2/anthropic-officially-bans-using-subscription-authentication-for-third-party-claude-use). Our design drives the official `claude` binary that Burak is logged into, headlessly, for his own use — the same thing the pocketbook server does today and the same mechanism Paperclip's `claude_local` uses. That is not the banned case on its face, but it is close enough that Burak should read his plan's current terms before building on it, and the design keeps the engine behind an adapter so it can fall back to API-key billing (or Codex) for any role if needed.

## Second pass — re-scored against A–H (same day; new evidence only)

- **Context signal is documented, not scraped.** Claude Code's statusline JSON exposes `context_window.used_percentage / remaining_percentage / context_window_size / current_usage`, `rate_limits.five_hour|seven_day.used_percentage`, and `session_id` (https://code.claude.com/docs/en/statusline); Codex app-server emits `thread/tokenUsage/updated` (replayed after resume/fork — https://github.com/openai/codex/pull/18023). Community monitors (ccusage 18.2k★ — 16 CLIs incl. Codex; ccstatusline; cc-ledger with runaway-session detection) read the same data. **Nothing rotates sessions automatically** — that stays ours.
- **Remote Control already has a Decision/FYI split at the notification level**: "push when actions are required" vs "push when Claude decides" (https://code.claude.com/docs/en/remote-control). `/insights` suggests CLAUDE.md rules but is manual copy, no provenance.
- **Rule provenance (F): no tool implements it.** Closest sketches: **claude-evolve** (16★ — rules carry `id / score / created / source / evidence`, EMA fitness, dormant after low score, dead after 15 dormant sessions; https://github.com/jack60810/claude-evolve); **ACE** (playbook bullets with ids and helpful/harmful counters, deterministic deltas; API-only; https://github.com/ace-agent/ace); OpenClaw's gated "dreaming" promotion with human-reviewable `DREAMS.md`; Paperclip's skill provenance (source badge / audit / version, v2026.529). None has incident/evidence links, verify-how, or a recurrence audit. Borrow the fitness score and helpful/harmful counters into our ledger's relevance field.
- **Validation (E):** only **claw-orchestrator** (559★ — Planner/Coder/Reviewer "councils" on independent engines, durable run kernel; https://github.com/Enderfga/claw-orchestrator) and **Fusion** (Validator lane on a separate model; fails A — calls APIs) do it by default; `codex-plugin-cc` ships `/codex:adversarial-review`; `claude ultrareview` / `--advisor` are opt-in. Our "critique on the other engine by default" is not shipped anywhere.
- **OpenClaw weaker than it looked on A:** its CLI backends (`claude -p` on the subscription) are documented as *text-only fallbacks* with tools only via an MCP loopback (https://docs.openclaw.ai/gateway/cli-backends); the native runtime is API-key. Its task-ledger notification tiers (`done_only / state_changes / silent`) are an FYI channel worth copying. Kokoro works through its OpenAI-compatible TTS setting (truncation bug #41342 open).
- **Hermes** can only reach Claude via API key or Max extra credits (Codex via ChatGPT OAuth is fine); its Kokoro "command provider" pattern is a reference for audio digests.
- **Alternative ordering from the researcher:** try Paperclip *first* (two evenings — satisfies A, B, C, H out of the box; expect to hit the D/E/F gaps), then native (one evening). Recorded against decision 15; the disagreement is only about which evaluation goes first.

## Recommendation

1. **Build on the native Claude Code stack** per `ARCHITECTURE.md`, using Remote Control + `AskUserQuestion` as the phase-1 Decision gate, `claude --bg --name` + `claude agents` for L2s, cross-session messaging for report-back, http hooks for events. The custom code is the `cos` CLI, the personas, the state/rule ledgers, and the supervisor — all small.
2. **Spend one afternoon on Paperclip** before building phase 2's page: if its Decisions feed + Telegram plugin cover the inbox/approve/voice loop well enough, phase 2 shrinks to a Paperclip plugin for our L3 persona and ledgers; if its context-hygiene gap and company metaphor grate (likely), the page is justified. Either way the evaluation is cheap and its adapter code is a reference for ours.
3. **Do not adopt OpenClaw as the shell.** Borrow its memory and approval ideas.
4. **Re-check the landscape quarterly**: this space churned hard in 2026 (Vibe Kanban dead, Roo archived, Kilo acquired, Omnara pivoted, Gas Town handed to new maintainers, Symphony unmaintained-by-design).
