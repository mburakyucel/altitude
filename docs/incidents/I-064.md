- date: 2026-08-30
- task: apply-r-010-i-030
- project: altitude
- what happened: The L3 session could not release a merge hold or amend an incident: both alt commands were first denied by the auto-mode classifier and then parked on an approval prompt, in a non-interactive session. Earlier today an L2 was denied gh pr merge 56 (both the --delete-branch form and the API form) and blocked one step from done.
- evidence: 2026-08-30 12:16Z done-time-cleanup-never-removes-a-runnin (Codex L2, codex:4104197, turn 6): the L3-directed gh pr merge 84 --squash on a reviewed, green, mergeable two-file PR was refused by the Codex-side execution safety reviewer (squashing mutates the shared default branch and is costly to reverse); the L2 treated the gate as authoritative, made no retry, and blocked one step from done. amended: 2026-08-30 by l1 (promotion to docs/incidents, PR #89): correct the PATH claim in the second amendment
- was: "the L3 must invoke <repo>/bin/alt because alt is not on PATH" (the absolute checkout path is redacted to `<repo>` here and in the amendment above; the point is the absolute invocation form). That is stale: `engines.clean_env()` prepends `config.REPO / "bin"` to PATH for every nested launch (I-021, the same function every `claude -p` / `claude --bg` / `codex exec` call goes through), so `alt` *is* on PATH in every session Altitude starts. The real fault had two parts: (1) the L3's allowlist matched only the bare `alt *` form while the session sometimes chose the absolute invocation (`/…/bin/alt task hold-merge …`), for which no rule existed, so those calls fell to the classifier; (2) L2 and L1 Claude sessions received no `gh` or `git` rules at all — `dispatch.session_settings()` carried only hooks and env, and `engines.claude_settings()` only `autoCompactWindow` — so every `gh pr merge`, `gh api …/pulls/…/merge` and `git reset --hard origin/main` was the classifier's call. Fix (this PR): `altitude/permissions.py` is the one table — both `alt` forms, the `gh` verbs a role needs, the `gh api` merge route of the checkout the session runs in, bounded `git` forms with the space before every wildcard — rendered into every Claude launch's settings `permissions.allow` (one `claude-settings*.json` per repository) and into the L3's `--allowedTools` at turn time; `hooks/permission_prompt_fault.py` turns any prompt that still appears into a counted `permission_denials` and a `permission-prompt` system fault (decision 36). Codex sessions are unchanged: `codex exec` takes no per-launch rules file, so the Codex-side refusals above stay open on that engine.
