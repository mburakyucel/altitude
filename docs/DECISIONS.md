# Decisions

Format follows career-platform: number, decision, why, what it costs. Everything below came out of a brainstorm on 2026-08-29 and is **proposed** until Burak settles it — once settled, don't relitigate without new information. The assessment section at the bottom sorts the brainstormed ideas into keep / adjust / defer with the reasoning, so the pushback is on record next to the idea.

## Open — need Burak

- **CoS engine default:** Claude (recommended for v1: bidirectional stream-json, Remote Control, hooks) vs Codex.
- **Default approval policy per project:** everything gated (recommended for career-platform) vs routine classes auto-approved (fine for prep tools).
- **Where `altd` runs:** the always-on PC next to `tutor.service` (recommended) — or nowhere for phase 0.
- **Second-opinion critique:** on by default for high-impact proposals only (recommended) vs always vs never.
- **Subscription policy check:** confirm that driving the logged-in `claude` binary headlessly for personal automation is within the current plan terms (Anthropic bars third-party harnesses from claude.ai OAuth as of 2026-04-04). Same question for Codex. Fallback per role is API-key billing or the other engine.

## Assessment of the brainstormed ideas (Claude's read, for sorting — not settled)

| Idea | Verdict | Why |
|---|---|---|
| One L3 coordinator per project above the existing L2/L1 pattern | **Keep — this is the product** | It attacks the actual bottleneck (organization, not quota) and reuses everything that already works. |
| Decisions vs FYIs as separate channels | **Keep** | Cheapest, highest-leverage rule in the whole design; most of the load reduction comes from here and from L3 answering L2 questions out of project docs. |
| Subscription CLIs headless, no Agent SDK/API | **Keep (forced)** | SDK is API-billed; the pocketbook server already proves the headless path on the seat. |
| Deterministic approvals via the surface, verbatim quote in the log | **Keep** | The one failure that must be structurally impossible. |
| Session rotation from checkpoints instead of trusting compaction | **Keep** | Matches how career-platform already survives compaction; makes "restart loses nothing" testable. |
| Automatic validation of proposals (other engine) and PRs | **Keep, budgeted** | Already done by hand; proposals are cheap relative to execution. Watch the cost on small tasks — allow per-class opt-out. |
| Context/quality monitoring by the supervisor | **Keep** | Cheap to compute from transcripts; removes a chore Burak does today. Thresholds are guesses until phase 0. |
| L3 creates/updates/deletes skills and rules on its own, reported as FYI | **Keep, with decision 14** | My first read was "gate it" because agent-written rules drift into bloat. The rule-ledger idea (provenance, probation, weekly audit for recurrence/relevance/staleness) addresses that directly, so FYI-with-veto is fine for non-guardrail rules once the ledger exists. Guardrail changes stay Decisions. |
| Rule ledger with provenance and periodic audit | **Keep — one of the best ideas in the brainstorm** | Turns "self-improving instructions" from a liability into something evaluable; also the mechanism by which Burak stops writing CLAUDE.md lines by hand. |
| Direct messaging to an L2 from Burak | **Keep, expect it to be rare** | Useful escape hatch; two writers to one session is fine if mirrored into `qa.md`. If it becomes common, the L3 persona is failing and that is the thing to fix. |
| Audio digests for the commute | **Keep, phase 2** | Kokoro and the Listen tab exist; it is rendering, not architecture. Not on the critical path. |
| Multi-provider (Claude + Codex) | **Keep at the adapter; v1 CoS on Claude** | Codex is best used as L2 and as the critic; two CoS implementations in v1 doubles persona tuning for no gain. |
| Custom web/phone app vs Remote Control | **Adjust: RC first, page second** | RC gives a phone loop on day one; the page earns its build by the things RC can't do (deterministic Approve, inbox, audio). |
| Open-sourcing | **Defer** | Keep the design generic (state on disk, engine adapter), decide after it has run on three of Burak's projects for a month. |
| Fully autonomous 24/7 operation | **Reject (as Burak already did)** | Human gate on Decisions is the design, not a limitation. |

Two things the brainstorm did not raise that need a decision eventually: (1) **L3 is a single serial session per project** — while it is working one turn it cannot answer another; the design keeps its turns short and pushes all heavy work into spawned sessions, but a project with many simultaneous conversations may want two coordinators or a queue — defer until it hurts. (2) **Summaries of summaries** — Burak reads L3's digest of L2's report of L1's work; the mitigation is that every digest links to its artifact and "why" questions are answered by reading it, and the git verification step keeps the chain honest.
